# Couriers Gambit — TestFlight Tester Instructions

Thank you for helping validate the MVP. The goal is to learn whether **route planning is intrinsically fun**, not to stress every edge case.

## Install

1. Accept the TestFlight invite for **Couriers Gambit**.
2. Install the latest build from the **Internal** or **External** group.
3. Launch the app — you should see the main menu.

## Core loop (about 20–30 minutes)

1. Tap **Start Game**. First launch shows a short **How to Play** — you may skip it.
2. Play **Jobs 1 → 5** in order:
   - Build an orthogonal route from Depot to Destination.
   - Use **Undo** freely while planning.
   - Watch Target Time, Deadline, delay/damage risk, and maximum reward in the summary.
   - **Confirm Route**, watch execution, then read Results (reward breakdown + recap).
   - Tap **Continue** for the next job.
3. After Job 5, use the **replay picker** to replay any job and try a different route.

## Focus questions

Please note briefly (notes app / feedback form is fine):

1. Did you understand how to build and confirm a route?
2. Did Target Time vs Deadline make sense?
3. Did delay risk and damage risk change how you chose a path?
4. Which route did you pick on your favourite job, and why?
5. Did alternatives feel meaningful, or did one path feel obviously best?
6. Did the Results screen feel fair / understandable?
7. Did you want to retry or compare another route?
8. Strongest job? Weakest job?

## Seeded jobs

| # | Name | What to notice |
|---|---|---|
| 1 | Direct but Risky | Short risky path vs safer detour |
| 2 | Predictable Detour | Longer sure route vs shorter uncertain route |
| 3 | Fast Lane Temptation | Whether Fast Lane is worth using |
| 4 | Deadline Pressure | Tight timing — composition matters |
| 5 | Close Decision | Two comparable options |

## Known limitations

- Only these five jobs (no random jobs yet).
- No upgrades, currency spending, or persistent career progress.
- Simple visuals; no audio/haptics polish beyond what’s in the build.
- Missing the Deadline fails the run with **zero** reward by design.

## If something breaks

Note: job name, roughly what you tapped, and whether it was during planning, execution, or results. Screenshots help.
