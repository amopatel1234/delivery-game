# Decision Log

This document records accepted product decisions that materially affect the MVP.

| ID | Status | Decision |
|---|---|---|
| DG-001 | Accepted | The MVP exists to validate whether route planning is intrinsically fun. |
| DG-002 | Accepted | Initial release targets iOS using SwiftUI on iOS 26. |
| DG-003 | Accepted | The playable grid is fixed at 5×5. |
| DG-004 | Accepted | The full grid is visible before planning begins. |
| DG-005 | Accepted | Movement is orthogonal only. |
| DG-006 | Accepted | Planning and execution are separate phases. |
| DG-007 | Accepted | Undo is unrestricted during planning. |
| DG-008 | Accepted | The player optimises for reward rather than shortest distance. |
| DG-009 | Accepted | Jobs define both a Target Time and a Deadline. |
| DG-010 | Accepted | Fast Lane replaces the earlier guaranteed reward concept. |
| DG-011 | Accepted | Heavy Traffic resolves with a 50% delay chance followed by a 15% damage chance if delayed. |
| DG-012 | Accepted | Damage exists only for the current run and never persists between jobs. |
| DG-013 | Accepted | The UI displays the maximum achievable reward. |
| DG-014 | Accepted | Star ratings are removed from the MVP. |
| DG-015 | Accepted | Five deterministic seeded jobs are used for MVP validation. |
| DG-016 | Accepted | Seeded jobs are played sequentially, then become freely replayable. |
| DG-017 | Accepted | Random jobs are introduced only after the seeded MVP has been validated. |
| DG-018 | Accepted | Delivery Game remains the internal project name. |
